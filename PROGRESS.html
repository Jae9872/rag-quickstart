How it works

1. Get a Gemini API key DONE

What: Jae created a Gemini API key in Google AI Studio with his Google Pro account.

Why: The RAG app needs a brain for generation. Gemini's free tier needs no card, and the key stays on Jae's machine only, in a .env file that is never uploaded.

Terminal check:

ls -la .env  # exists locally, never committed
grep -c GEMINI_API_KEY .env  # should print 1

2. Build the RAG app DONE

What: FastAPI app with local embeddings (all-MiniLM-L6-v2), ChromaDB storage, and a one-page UI. Ask a question, get an answer with the source chunks shown underneath. Providers: Gemini key first, then Groq, then local Ollama/Hermes, then extractive mode with no key at all.

Why: This is the product. Retrieval by meaning plus cited sources is the whole point of RAG, and it is the skill ClaimSorted hires for: agents that ground answers in real documents instead of guessing.

Terminal:

cd ~/workspace/rag-quickstart
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000

3. Run it and test with 3 questions IN PROGRESS

What: Start the server, open http://localhost:8000, and ask 3 questions about the seeded documents. Confirm each answer cites the right chunk.

Why: Nothing counts until it runs. A test with known answers proves retrieval works before real users touch it.

Terminal:

curl -s http://localhost:8000/health
curl -s -X POST http://localhost:8000/ask -H 'Content-Type: application/json' \
  -d '{"question": "What does ClaimSorted do?"}'

5. Push the code TODO

What: Push the app, README, and seed docs. The .env file stays out via .gitignore.

Why: If the key leaks into git history, it must be revoked. The .gitignore check is the safety step before any push.

Terminal:

cd ~/workspace/rag-quickstart
cat .gitignore  # must contain: .env
git add . && git commit -m "Minimal RAG starter with cited answers"
git push -u origin main
